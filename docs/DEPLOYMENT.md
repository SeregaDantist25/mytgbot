# Размещение рабочего бота

Ветка для приёмки: `dev/mytgbot-v2`. Бот работает как один постоянный worker
с Telegram long polling; HTTP-порт ему не требуется.

## Обязательные переменные

- `TELEGRAM_BOT_TOKEN` — токен тестового или рабочего Telegram-бота;
- `ADMIN_IDS` — Telegram ID владельцев через запятую;
- `DATABASE_URL` — PostgreSQL для постоянного размещения.

Необязательные AI-переменные перечислены в `.env.example`. Без них создание
актов и основная навигация продолжают работать локально.

## Docker

```bash
docker build -t mytgbot-v2 .
docker run --env-file .env mytgbot-v2
```

Перед запуском контейнер выполняет `manage.py check`. При отсутствии токена или
утверждённого XLSX-шаблона процесс завершится с понятной ошибкой.

## Render, Railway, Koyeb и аналоги

1. Подключить репозиторий и ветку `dev/mytgbot-v2`.
2. Выбрать Dockerfile либо worker-команду `python manage.py run`.
3. Добавить обязательные переменные окружения.
4. Создать ровно один экземпляр worker: два polling-процесса с одним токеном
   будут конфликтовать.
5. Для постоянной модели использовать PostgreSQL. SQLite допустим только при
   подключённом постоянном диске и одном экземпляре.

После запуска проверить в Telegram: `/start`, `/login`, «🚢 Суда», выбор пункта
ведомости и создание тестового акта.
