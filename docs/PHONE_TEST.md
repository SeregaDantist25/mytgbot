# Тестирование бота только с телефона

Компьютер и платный хостинг для временной проверки не требуются. GitHub Actions
запускает тестового бота на 20 минут. База этого запуска временная и удаляется
после завершения задания.

## 1. Создать тестового бота

1. Открыть официальный аккаунт `@BotFather` в Telegram.
2. Отправить `/newbot`.
3. Указать отображаемое имя.
4. Указать уникальный username, заканчивающийся на `bot`.
5. Скопировать полученный токен. Не отправлять его в сообщения и не сохранять
   в файлах репозитория.

## 2. Сохранить токен в GitHub

В браузере телефона открыть репозиторий `SeregaDantist25/mytgbot`, затем:

1. `Settings`.
2. `Secrets and variables` → `Actions`.
3. `New repository secret`.
4. Name: `TEST_TELEGRAM_BOT_TOKEN`.
5. Secret: токен, полученный от BotFather.
6. Нажать `Add secret`.

После сообщения владельца о готовности запускающий коммит создаётся в ветке
`dev/mytgbot-v2`. Токен не читается из GitHub и не появляется в логах.

## 3. Первый запуск и получение Telegram ID

Когда временный бот запущен:

1. Открыть созданного бота в Telegram и нажать `Start`.
2. Отправить `/myid`.
3. Скопировать показанное число.
4. В GitHub рядом с токеном создать второй repository secret:
   `TEST_TELEGRAM_ADMIN_IDS`, значение — полученное число.

После этого требуется повторный запуск. Команда `/login` автоматически создаст
владельца из `TEST_TELEGRAM_ADMIN_IDS` как одобренного инженера-технолога.

## 4. Минимальная приёмка

Во время второго 20-минутного запуска проверить:

1. `/login` — регистрация владельца.
2. `/start` — главное меню.
3. `Суда` — доступ к навигации.
4. Добавление тестового судна при пустом списке.
5. Загрузку ремонтной ведомости XLSX.
6. Выбор раздела и пункта.
7. `Создать акт дефектации (AI)`.
8. Получение заполненного XLSX-файла.

Постоянное хранение данных и круглосуточная работа появятся только после выбора
производственного хостинга.
