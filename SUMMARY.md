## 📁 Новые файлы

### 1. `document_states.py` (20 строк)
Определяет состояния для работы с документами:
- `waiting_for_file` — ожидание загрузки
- `waiting_for_replacement` — ожидание замены
- `confirming_delete` — подтверждение удаления
- `waiting_for_category` — выбор категории

### 2. `document_handlers.py` (280 строк)
Обработчики для StatesGroup:
- Загрузка документа с выбором категории
- Замена draft-документа
- Удаление с подтверждением
- Регистрация всех обработчиков

### 3. `document_utils.py` (150 строк)
Утилиты для работы с документами:
- `handle_document_replace()` — замена draft
- `convert_to_pdf()` — конвертация в PDF
- `_convert_docx_to_pdf()` — DOCX → PDF
- `_convert_xlsx_to_pdf()` — XLSX → PDF
- `handle_document_approve_with_pdf()` — утверждение с конвертацией

### 4. `category_handlers.py` (150 строк)
Обработчики для навигации по категориям:
- Показ категорий для пункта
- Показ документов по категории

- Построение клавиатур с действиями

### 5. `PLAN.md` (127 строк)

### ✅ 2. Интеграция категорий документов в меню (высокий приоритет)
**Статус:** ЗАВЕРШЕНО

**Что сделано:**
- ✅ Функции для получения категорий и документов
- ✅ Клавиатуры для навигации по категориям
- ✅ Показ документов с версией и статусом
- ✅ Обработчики для всех callback-кнопок
- ✅ Интеграция в navigation.py

**Логика:**
1. Пользователь выбирает пункт → показываются категории
2. Пользователь выбирает категорию → показываются документы
3. Каждый документ: "v1 (draft)" или "v2 (approved)" или "v3 (archived)"

**Callback-структура:**
- `categories_<item_id>` — показать категории
- `docs_<item_id>_<category>_<page>` — показать документы
- `doc_<doc_id>` — показать детали

### ✅ 4. Редактирование/замена документа (средний приоритет)
**Статус:** ЗАВЕРШЕНО

**Что сделано:**
- ✅ Функция `handle_document_replace()` для замены draft
- ✅ Обработчик кнопки "Заменить"
- ✅ Состояние `waiting_for_replacement`
- ✅ Сохранение с тем же item_id и category
- ✅ Версия остаётся той же

**Логика:**
1. Пользователь нажимает "Заменить" на draft-документе
2. Бот переходит в состояние `waiting_for_replacement`
3. Пользователь отправляет новый файл
4. Старый файл удаляется, новый сохраняется
5. Версия и статус остаются неизменными

**Callback:** `replace_<doc_id>`

### ✅ 5. Конвертация в PDF (низкий приоритет)
**Статус:** ЗАВЕРШЕНО

- ✅ Функция `convert_to_pdf()` для конвертации

- ✅ Функция `handle_document_approve_with_pdf()`
- ✅ Интеграция с утверждением документа

**Логика:**
1. При утверждении документа (draft → approved)
2. Если файл DOCX или XLSX → конвертировать в PDF
3. Если файл уже PDF → оставить как есть
4. Сохранить PDF в хранилище
5. Обновить `file_ref` в БД

**Инструменты:**
- `python-docx` — для DOCX
- `openpyxl` — для XLSX
- `reportlab` — для создания PDF
